# Instrucciones del proyecto para asistentes de codigo

Este archivo lo leen automaticamente las herramientas de asistencia
(Aider, Cursor, Claude Code, etc.) al iniciar una sesion en este repo.
`AGENTS.md` es una convencion abierta — no es propietaria de ningun
proveedor. Las reglas de aca son obligatorias para cualquier cambio.

## Atribucion de commits

**NO agregues lineas `Co-Authored-By:` referenciando al asistente.**

Esto incluye coautorias y firmas de cualquier herramienta de AI
(Claude, Copilot, ChatGPT, Aider, Cursor, etc.), y tambien frases
del estilo "Generated by ..." o "Made with ..." al final del mensaje.

Los commits deben ir con el autor configurado en `git config user.name`
y `git config user.email`, sin coautores artificiales. El historial git
es la fuente de verdad legal del trabajo — atribuir a herramientas no
aporta y dificulta el ownership.

Tampoco agregues referencias al asistente en:
- Comentarios de codigo
- Documentacion
- Mensajes de log
- Nombres de archivos
- Templates de issues o PRs

Si necesitas mencionar como se hizo algo, describi la decision o el
contexto tecnico, no la herramienta.

## Estilo de commits

- En espanol (idioma del proyecto).
- Imperativo en presente: "Fix bug X", "Add feature Y" — no "Fixed" ni "Adding".
- Primera linea ≤ 72 chars, resumen de QUE y POR QUE (no como).
- Si el commit toca varias areas, usar prefijo: "POS: ...", "Tienda: ...",
  "Deploy: ...", "settings: ...".

## Codigo

- Idioma de dominio: espanol (productos, ventas, clientes, etc.).
- Codigo Python: comentarios y docstrings en espanol neutro o chileno.
- Variables y funciones: ingles tecnico (`save`, `delete`, etc.) o
  espanol consistente segun el modulo (`bodega/`, `pos/` usan espanol).
- Sin tildes en docstrings/comentarios cuando se pueda — algunos entornos
  Windows (cp1252) las rompen.

## Tests

- No hay test runner CI configurado todavia. Tests manuales en `runserver`.
- Antes de commitear cambios grandes: `python manage.py test` debe pasar
  todos los tests menos los preexistentes (~2 fallos por NBSP en
  `intcomma` con Python 3.9 + Django 4.2 — esperables).

## Despliegue

- Branch principal: `master`.
- Servidor de prod: ver `OPERACIONES.md`.
- Cambios en `deploy/` requieren tests manuales en una VPS de staging
  antes de tocar prod.
